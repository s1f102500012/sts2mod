# 更好的角色遗物

作者：Natsuki。模组版本：1.1.3。维护的游戏版本：0.107.1、0.111.0。

支持简体中文、英文、日文，包含观者可选强化的本地化描述。

重做五位角色的初始遗物及升级遗物。保留原版遗物类型、ID 与存档格式，没有自定义模型或 SavedProperty，不依赖第三方基础库。

观者为可选前置，支持 lamali（创意工坊 3747492505）或 Boninall（3747526116）版本，任选其一并满足该观者自身的游戏版本和依赖要求。本模组的双版本支持不改变第三方观者的兼容范围；两种观者的 mod ID 都是 Watcher，不建议同时安装。

- 至纯之水：在每场战斗开始时，将1张奇迹放入你的手牌，并获得2层真言。
- 圣水：在每场战斗开始时，将3张奇迹放入你的手牌，并获得5层真言。

保留原作者的奇迹生成、遗物类型和升级关系，只追加其自身真言能力。没有安装观者时，本模组仍可独立使用。描述中数字为蓝色，奇迹和真言为金色，遗物悬停提示追加真言规则。联机时所有玩家须选择相同观者实现和版本。

## 安装与兼容

将发布包内整个 `BetterCharacterRelics` 目录放入游戏 `mods` 目录，保留 `lib` 子目录。根 DLL 是加载器，两个 `lib/<游戏版本>/BetterCharacterRelics.dll` 分别针对对应原版引用编译。不要只复制根目录的三个文件。

所有联机玩家应使用相同游戏版本和本模组版本。未验证的中间版本会选择不高于宿主的最近变体并给出提示；这不表示维护或验证了其它游戏版本。未知版本选择最新变体并明确警告。

加载器只使用公开版本信息与公开程序集关联 API；本模组没有模型类型，因此不注入模型发现入口或联机序列化表。构建时的 SHA-256 清单用于核对交付文件，不在玩家启动时阻止自行编译或修改的 DLL。

## 构建与检查

需要 .NET 9、游戏本体、以下两个引用目录：

- `../HextechRunes/versioned-dll-backups/0.107.1/game-refs`
- `../HextechRunes/versioned-dll-backups/0.111.0/game-refs`

本公开镜像不包含游戏程序集。默认引用路径沿用开发工作区结构；单版本构建或检查时，也可用 `-p:GameDataDir=<对应版本的程序集目录>` 指定自己的引用路径。两个游戏版本必须分别使用对应的引用，不能共用当前安装版本的 DLL。

仅构建、检查并打包：`python3 tools/build_bundle.py`。

构建并部署：`tools/build_and_deploy.sh`。部署前保存旧包备份，部署后逐文件核对。脚本不上传创意工坊。

单版本检查：`dotnet run --project tests/BetterCharacterRelics.Tests.csproj -c Release -p:GameVersion=0.107.1 -- <本模组绝对路径> --runtime-patches`，另一版将目标替换为 `0.111.0`。不支持的构建目标会被项目拒绝。

`tests/snapshots/<版本>` 包含补丁、可变静态字段、SavedProperty、加载器字段以及原版 IL 快照。测试通过反射读取声明，不执行 Prepare/TargetMethod。`--runtime-patches` 在独立 .NET 进程中实际安装补丁并导出表，但不执行游戏战斗。

更新快照必须先审查差异，再显式使用 `--accept-snapshots`；常规构建只比对，不接受新快照。原版 IL 快照同时包含 async 入口和 MoveNext，游戏启动时逐项报告漂移。

## 行为边界

1.1.2 保留既有治疗量、星辉阈值、召唤量、抽弃牌数量、集中数量与触发时机。戒指继续按全局轮数判断，额外个人回合不会因此少一次收益。`InfusedCore` 的游戏效果维持原状。

原版遗物重做与同一遗物的其它重做模组仍可能存在设计冲突；低优先级和诊断能使冲突可见，不能承诺任意重做同时生效。
